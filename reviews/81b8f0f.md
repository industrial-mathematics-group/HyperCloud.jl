## Findings

### 1. BGK `SlipWall` reflects about the velocity-grid centre, not about the wall, when `:PDE_vcenter ≠ 0` — medium — CONFIRMED
- **Where:** `src/BoundaryConditions/_main.jl:68-71` (`_specular`, node-flip branch), via `_flipped_index:50-54`; also the specular part
  of `DiffuseWall` with `α < 1` (`:140`).
- **What:** the flip maps node index `i → NV1 + 1 − i`, i.e. `v = c + ν_i → c − ν_i`: a reflection about the grid centre `c`
  (`BGKEquation.center`, the documented key `:PDE_vcenter`, `docs/src/configuration.md:36`). For a static wall the reflection must
  be about 0 (generally about `w·n`). With `c_n ≠ 0` the ghost carries the momentum `2 c_n ρ` and the wall is penetrable.
  `iszero(w)` is checked, `eq.center` is not.
- **Evidence:** `ops.jl`: gas at rest, `vcenter = 0.5`, static wall: ghost momentum 1.0 (mirrored 0.0), net wall mass flux 0.316
  (`vcenter = 0.3`: 0.6 / 0.228); the diffuse wall is exact in the same case (1e-15), since it uses the true velocities.
  `runs.jl vcenter`: the walls-test equilibrium (1-D, Nv = 16, slip walls, t = 0.5): `vcenter = 0` max deviation 8.9e-16;
  **`vcenter = 0.5`: deviation 2.09, mean density +20.7 %, mean momentum 0.70** — silently wrong physics.
- **Fix:** take the flip only when the reflection maps the grid onto itself, i.e. `ax > 0 && eq.center[ax] == w[ax]`
  (`v → 2 w_n − v`; this also makes a wall moving at the grid-centre velocity exact) and otherwise use the general path;
  reflect `v − 2((v − w)·n) n` in the general path (it already does). Add a `vcenter` case to the `walls` tests and say in the
  docstring that the flip needs a grid centred at the wall's normal velocity.

### 2. Specular BGK reflection off the axis or on a moving wall is not conservative and does not keep equilibrium — medium — CONFIRMED
- **Where:** `src/BoundaryConditions/_main.jl:72-78` (nearest-node path), used for every normal that is not along an axis
  (curved walls, spheres, oblique planes, `Moving` rotating pieces) and for every moving wall; inherited by `DiffuseWall(α < 1)`
  (`:140`). Docs: `SlipWall` docstring, `docs/src/walls.md:8` ("exact node flip for a wall along an axis").
- **What:** every component takes the value of the node nearest to its reflected velocity. The map is not a bijection of the
  grid, so the ghost distribution has different mass, energy and normal momentum than the exact reflection, and the
  half-range mass flux at the wall does not vanish. For a moving wall the reflected velocities are off-grid by up to Δv/2: in 1-D
  with Nv = 16, vmax = 6 (Δv = 0.75) the ghost is the same for `w = 0.2` and `w = 0.5` (both reflect about 0.375). The docstring
  says "Use DiffuseWall for moving kinetic walls", but the consequences (and the off-axis case at all) are not stated, and
  `slip_wall()` is the default reflecting wall of the docs table.
- **Evidence:** `ops.jl`, 2-D Nv = 12, drifting equilibrium: θ = π/8, π/6, 0.3: only 107 / 116 / 104 of 144 distinct target nodes;
  ghost density ×0.971 / ×0.902 / ×1.016, energy ×0.960 / ×0.930 / ×1.053; net wall mass flux 3.2e-2 / 3.9e-2 / −2.2e-2
  (diffuse α = 1: ≤ 2.6e-16; α = 0.5: half the slip values). θ = 0 and π/4 (corner diagonal) are exact. 1-D moving wall:
  mass flux relative to the wall −0.118 (w = 0.5), +0.165 (w = 0.2); `DiffuseWall(α = 0.5 / 0)` on a wall moving at ±0.5:
  −0.045 / −0.090 and +0.080 / +0.160 (α = 1: 1e-16). Runs: `alloc2d.jl` 2-D disk at rest, t = 0.1: slip deviation 9.1e-2 and mass
  +1.8e-3, α = 0.5 5.2e-2 (diffuse 1.8e-15); `runs.jl bgk` BGK piston with `slip_wall()` on the face: ρ −9.1 %, p −12.8 %,
  u −0.374 instead of −0.5.
- **Fix:** at least: state in the docstring and `walls.md` that off-axis and moving specular reflection (and `α < 1` there) is
  approximate and neither conserves mass nor keeps an equilibrium (with the numbers above), and throw or `@warn` once
  for a moving `SlipWall` on BGK. Better: a conservative specular map, e.g. linear interpolation of `f` at the reflected
  velocity with a moment correction of the reflected half (mass, normal flux), or reflect the incident half-range moments
  and emit a discrete Maxwellian/Grad closure. For moving 1-D walls Finding 1's fix (grid centred at the wall velocity)
  gives an exact flip.

### 4. `:stopped_early` is `false` for a run that blew up but reached `tmax` — medium — CONFIRMED
- **Where:** `src/device.jl:151`; docs `docs/src/simulation.md:29-31` and the `run_metadata` docstring ("a blown-up run is stored
  like any other; … this flag keeps it findable later").
- **What:** the flag only compares `t_final` with `tmax`. Blow-ups that the step does not see (fixed `dt`, constant wave speeds)
  are only detected at stored snapshots; with `snapshots = 1` (all `walls` tests, many scripts) or a blow-up in the last
  interval, the loop runs to `tmax` and `_check_snapshot(…; final = true)` only warns. The run is cached with non-finite data and
  `stopped_early = false`, exactly the case the docs tell users to check the flag for.
- **Evidence:** `meta.jl`: the existing test case `pb1` (`test/sims.jl:88`, linear advection CFL 5, `snapshots = 1`):
  `t_end = 100.0`, final state not finite, metadata `stopped_early => false, t_final => 100.0`; `pf` (`test/sims.jl:101`, Sod at
  fixed `dt = 0.05`, `snapshots = 1`): `t_end = 0.2`, not finite, `stopped_early => false`.
- **Fix:** add `:finite => all(u -> all(isfinite, u), last snapshot)` (or a `:blown_up` flag returned by `solve_equation`) to the
  metadata and document "check `stopped_early` and `finite`", or define `stopped_early` as "did not reach `tmax` with a finite
  state". Extend the `pb1`/`pf` tests with the metadata check.

### 5. The run hash ignores the motion of a `Moving` piece; the example's `:piston_speed` does not drive the run — medium — CONFIRMED
- **Where:** `src/Examples/euler_1d_piston.jl:56, 67-71`; `exact_piston:41-52`; docs `walls.md:16-23` (snippet), `configuration.md`
  (`:shape` row).
- **What:** PDEStudioCore normalises closures to `"Closure"` before hashing (`Serialization.jl:400-410`), and `translating((-w,))`
  is a closure (`HyperCloudCore.var"#translating##0#translating##1"{…}`), so the piston speed is not in the parameter hash: two
  runs with different speeds share one cache file and `@sim` (default `force_overwrite = false`) silently returns the stale one.
  The example records `:piston_speed`/`:piston_face` as separate global keys, but they are read only by `exact_piston`; the
  shape is built from the constant. Overriding `:piston_speed` (e.g. in `varied` or a copied config) changes the reference and the
  hash but not the piston; changing the shape only (as in the `walls.md` snippet) changes neither the hash nor the reference.
- **Evidence:** `hash2.jl`: example task hash equal for a shape rebuilt with `w = 0.5` and with `w = 0.4` (`true`, `true`);
  a different face position (a plain field) changes it.
- **Fix:** build the shape from the keys (`:Grid_shape` as a string of code, which the domain builder accepts and the hash keeps
  verbatim, e.g. `"intersect(Tagged(Cuboid((0.0,), (1.5,)), 1), Moving(Tagged(HalfSpace((1.0,), (1.0,)), 2), translating((-0.5,))))"`,
  or a builder that reads `:piston_speed`); say in `walls.md`/`configuration.md` that motions of `Moving` pieces are not hashed
  and must be mirrored in a hashed key. Longer term the motions in Core should be named structs (hashed by fields).

### 6. The mass-drift numbers mix a quadrature error into the wall error — low — CONFIRMED
- **Where:** `docs/src/walls.md:33`, `test/sims_walls.jl:124-127` (`drift` = mean of the particle densities − 1).
- **What:** the 1-D rectangular cloud has N + 1 particles including the two wall particles (x = 0 and 1), so the mean of the
  point values is not the mass (trapezoid weights would be); with a non-uniform final density this alone gives an O(Δx) "drift".
  Measured with trapezoid weights the slip-wall control is second order (the "mean" drift there is a pure artifact), and the
  diffuse hot wall drifts *more* than reported and with an order below 1 at these resolutions.
- **Evidence:** `quad.jl`, N = 50 / 100 / 200 / 400: hot diffuse wall Δmean 7.44e-3 / 5.02e-3 / 3.15e-3 / 1.87e-3, **Δtrapezoid
  1.15e-2 / 7.11e-3 / 4.21e-3 / 2.40e-3** (rates 0.70 / 0.76 / 0.81); slip walls with a pressure jump: Δmean 1.58e-3 / 8.9e-4 /
  4.7e-4 / 2.4e-4 (first order, artifact), Δtrapezoid −1.5e-4 / −3.9e-5 / −1.0e-5 / −2.7e-6 (second order). Euler slip walls,
  same IC, Δmean 1.2e-3 / 6.9e-4 / 3.8e-4 (`run2_control.out`).
- **Judgement:** a first-order mass error at a diffuse wall is expected for a ghost-state wall in a collocation scheme: the
  zero-flux condition holds for the ghost state, but the ghost carries a velocity-space jump (half-range Maxwellian) and the
  scheme's implied flux across the wall comes from the reconstruction through it, which is only first-order consistent for a
  non-smooth extension. Exact conservation would need a flux-form wall (the half-range flux balance applied as the wall flux).
  The conclusion in the docs stands; the numbers and the test metric do not.
- **Fix:** measure with trapezoid weights (or the grid's particle volumes) in the test and in `walls.md` (1.15 / 0.71 / 0.42 %,
  order → 1), and add the slip-wall control (second order) to show that the drift is the diffuse wall's.

### 7. The piston example does not run in Float32 — low — CONFIRMED
- **Where:** `src/Examples/euler_1d_piston.jl:56-57`.
- **What:** the shape is built in Float64; with `:T => Float32` the domain builder refuses it ("the shape has element type

- **Fix:** a string-valued `:Grid_shape` (Finding 5) parsed in the run's type, or let Core's `build_domain` convert a shape to `T`.

## Test coverage

- **The BGK equilibrium test (`test/sims_walls.jl:110-116`) does not test the operators:** an equilibrium at rest is symmetric, so
  any even reflection keeps it. `eqdisc.jl`: the same test with `MirrorBC()` (no operator) 2.2e-16, `ExtrapolationBC(1)` 4.4e-16,
  `OutflowBC()` 2.2e-16 — all pass. The unit checks `DiffuseWall(1.0)(bgk, feq, w1) ≈ feq` (`:56-57`) would pass for the identity
  too. Discriminating replacements: a drifting equilibrium (u ≠ 0) between slip walls (momentum must reverse), or the half-range
  mass flux of the ghost against a non-symmetric `f` (as in `ops.jl`).
- The hot-wall test does discriminate (α = 0 at the hot wall gives θ = 1.0000 next to it, outside `1.7 < θ < 2`), but its drift
  criterion uses the biased mean (Finding 6).
- Not covered: off-axis normals and moving walls for BGK specular / α < 1 (Finding 2), `vcenter` (Finding 1), Float32 runs with
  walls, 2-D/3-D walls at all (Euler operator unit test is 2-D, no 2-D/3-D run), a kinetic piston with the slip face.
- Euler shock reflection and piston: meaningful (a static reflection or no wall fails them); the "face within one spacing" check
  (`:96`) is tight and right (measured exactly Δx).
- PR #17: `stopped_early` is asserted only for the stopped case (`test/sims.jl:82`) and `false` for a normal run (`:274`); the
  blow-up-reaching-tmax cases `pb1`/`pf` in the same testset do not check it (Finding 4). The `@sim` tests use an empty config, so

  (e.g. `calculate_stats = false`). Before the change the new assertions fail by construction (`metadata` has no
  `:stopped_early`, `@sim` with two arguments has no method; by reading, not run).

## Minor issues

- `src/BoundaryConditions/_main.jl:127`: `ok || return f` — if the wall Maxwellian fails (extreme θ_w on a coarse grid) the ghost
  silently becomes the even reflection (no wall at all). A one-time warning, or the continuous Maxwellian normalised on the grid, would be safer.
- `:117`: a `velocity` of the wrong length (`DiffuseWall(1.0; velocity = (0.1, 0.2))` in 1-D) is a `MethodError` in the kernel at the
  first step (a GPU compile error). D is unknown at construction, but `diffuse_wall` could be checked in the runner/builder.
- `:76`: the nearest-node search is O(NV) per component, O(M·NV) per ghost (5 µs at M = 128; ~16× that at Nv = 16 in 2-D); with
  Finding 2's fix this disappears, otherwise precompute the target table when the normal is constant.
- `SlipWall`/`DiffuseWall` on unsupported equations: a dedicated fallback `(::SlipWall)(eq, U, wall) = throw(ArgumentError("SlipWall
  is defined for Euler and BGK, not $(typeof(eq))"))` would give a clearer message than a MethodError from inside the kernel; the
  bigger gain would be a host-side check before the run (e.g. `applicable` on the first ghost).
- `src/Examples/euler_1d_piston.jl:24`: the bisection bracket `hi = 1000 p₁` caps the piston speed (`g(1000 p₁) ≈ 28.8 √(p₁/ρ₁)` for
  γ = 1.4, i.e. w ≳ 24 c₁; beyond that `p₂ = hi` silently). Expand the bracket until `g(hi) > 0`.
- `docs/src/walls.md:30`: "shock reflection … to 1e-3" (commit message) holds for p; ρ is 1.8e-3 off (2.0774 vs 2.0792).
- `src/device.jl:146`: `:backend => "KABackend"` does not distinguish POCL CPU from ROCm/CUDA devices; `string(typeof(get_backend()))`
  or the device name would. `:t_final` in Float32 is stored as `0.30000001192092896` (cosmetic).
- `@sim name dry_run = true dry_run = false` fails with a lowering error ("field name repeated in named tuple") pointing into
  `src/macros.jl:174`, not the user's line; a duplicate-key check next to the existing ArgumentError would be clearer.
- Parameter hash of a `:Grid_shape` contains the generated closure type name (`var"#translating##0#translating##1"`): stable
  across processes now, but a Core edit that renumbers closures would change every shape run's hash (also an argument for
  named motion structs, Finding 5).

## Verdict

The Euler slip wall is correct (static and moving, 1–3-D, Float32, allocation free, `ka_cpu`), the piston example and its exact
Rankine–Hugoniot reference are right, and every number in the commit message and `walls.md` reproduces (reflection plateau,
piston 1.4895, equilibrium 2.2e-16, hot wall 0.74/0.50/0.32 %, BGK piston −0.5/−0.75 %). The diffuse wall's zero-flux construction is exact
for α = 1 on any normal and any wall velocity. The weak part is the BGK specular reflection: it is exact only for axis-aligned
static walls on a grid centred at zero; with `:PDE_vcenter ≠ 0` it reflects about the wrong velocity (a gas at rest gains 21 % mass),
and off-axis or moving it neither conserves mass nor keeps equilibrium (2-D disk 9 % deviation, BGK piston with a slip face 9–13 %
off), which also affects `DiffuseWall(α < 1)`. PR #17 is correct and documented, except that `stopped_early` misses blow-ups that
reach `tmax`. Two process issues: HyperCloud main_dev does not load with the registered HyperCloudCore 0.8.0 (compat not bumped),
and the hash ignores the piston motion. The full suite passes (1229/1229) and the `walls` group passes on `ka_cpu`, but the BGK
equilibrium test passes for any even reflection. Findings: **0 high, 5 medium, 2 low** (1: specular flip ignores `vcenter`;
2: off-axis/moving specular BGK not conservative; 3: compat/version vs registered Core 0.8.0; 4: `stopped_early` misses blow-ups at
`tmax`; 5: motions not hashed, `:piston_speed` decoupled from the shape; 6: mass-drift metric biased; 7: example not Float32).
