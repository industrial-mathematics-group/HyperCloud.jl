## Findings

### 1. The final snapshot is never checked: blow-ups in the last snapshot interval, and every blow-up with `snapshots = 1`, still finish silently — medium — CONFIRMED
- **Where:** `src/time_integration.jl:162` (the check runs only inside `while snap_counter <= snapshots && …`), `:217-219`
  (the final slot `snapshots + 1` is written after the loop without the check); docs `docs/src/time_integration.md:19-26` and the
  `solve_equation` docstring ("or if a stored snapshot is not finite"; "A snapshot that grew by more than a factor 1e8 … gives a warning").
- **What:** slot `snapshots + 1` is always written by the post-loop `saveData!`, so neither the non-finite check nor the growth
  warning ever sees it. With `snapshots = 1` (one output interval, typical for convergence/error sweeps, used in the suite at
  `test/runtests.jl:174` and `test/sims_bgk.jl:69`) the new detection is never executed, i.e. N1 is not fixed for those runs; with
  more snapshots a blow-up after `t_snap[snapshots]` goes unreported.
- **Scenario / evidence:** `probe_stop_new.out`: linear advection at CFL 5, tmax 100: `snapshots = 1` → `t = [0, 100]`, final
  max|u| = NaN, **no warning**; `snapshots = 2` → NaN at t = 100 with only the growth warning (no "not finite" stop); Sod MUSCL2
  without limiter at fixed `dt = 0.05`: `snapshots = 1` → NaN, no warning; `snapshots = 4` → NaN final state, only the growth warning.
- **Fix:** apply the same check to the post-loop save (warn "the state at t = … is not finite", no need to stop; and the growth
  warning), e.g. factor the check into a small helper called after every `saveData!`. Add a regression test with `:snapshots => 1`
  (the existing CFL-5 case with `snapshots = 1`, tmax 100, takes < 1 s).

### 2. An infinite step is accepted unconditionally: an all-NaN state or a fixed `:Time_dt => Inf` now jumps to tmax — low — CONFIRMED
- **Where:** `src/time_integration.jl:146` (`!(dt_step > 1e-12)` lets `Inf` through), `:152` (`dt_val = min(Inf, tmax - t)`);
  HyperCloudCore 0.7.9 `ParticleGrids.jl:386` (`sum_c > tol && …`: a NaN wave speed is skipped, so a grid whose interior is all NaN
  returns `Inf`, the same value as "no wave moves").
- **What:** N2's fix treats every `Inf` as "no wave moves". That is right for a finite stationary state, but `Inf` also comes from
  (a) a state that is NaN everywhere (a NaN input, or a nonlinear run once NaN has spread to every particle), and (b) a fixed
  `:Time_dt => Inf` (or `:Time_CFL => Inf`). In (a) the loop now advances to tmax in one step and records the NaN state at
  `t = tmax`; with `snapshots = 1` nothing is reported (Finding 1), otherwise the warning reads "stopped at t = 0.15 before
  tmax = 0.15 … The data end at t = 0.15" though the state was NaN from t = 0. At d4fe5e4 both cases stopped with a warning.
  In (b) one explicit step of size `tmax` is taken silently.
- **Scenario / evidence:** `probe_nan_new.out` (Burgers, `:IC_a => (NaN,)`): snaps = 1 → `t = [0, 0.15]`, NaN, no warning;
  snaps = 4 → warned, data labelled t = tmax; `probe_nan_old.out`: both stop at t = 0 with "time step is not finite (dt = Inf)".
  `probe_stop_new.out`: fixed `dt = Inf` → `t = [0, 0.1, 0.1]`, max|u| = 0.668 (wrong; one step at CFL 5), no warning.
- **Fix:** accept `Inf` only for a CFL step (`is_cfl && isfinite(dt_inp)`) and only if the state is finite (check `_max_abs` of the
  grid's state on that rare path; it is not the hot path); reject non-finite or non-positive `dt`/`CFL` up front with an
  `ArgumentError` (that also gives the negative/zero/NaN fixed-`dt` cases a precise message instead of "collapsed … the state has
  probably blown up", see Minor issues).

### 3. N3 only partly done: the repo `CLAUDE.md` still names `:Grid_bc_map` as an ignored key — low — CONFIRMED (by reading)
- **Where:** `CLAUDE.md:49` ("Misspelled keys are silently ignored (e.g. `:Grid_bc_map` instead of `:Grid_bc`)").
- **What:** the docs box (`docs/src/configuration.md:58-60`) and the test comment (`test/runtests.jl:150`) are now correct, but the
  file every agent reads first still gives the wrong example. Pick another example (e.g. `:Grid_bcs`).

### 4. The new BGK τ = 0 comment states a wrong tableau property — low — CONFIRMED (by reading)
- **Where:** `src/SourceTerms/bgk.jl:36-38`; HyperCloudCore `ButcherTableaus.jl:163-215`, `TimeSteppers.jl:350-356`.
- **What:** "all shipped tableaus have a zero first column and b[1] = 0" holds only for `IMEX_Euler` and `ARS233`. `ARS222`
  (`A[1,1] = g`, `A[2,1] = 1-g`, `b[1] = 1-g`), `PRSSP3` and `SSP2332` have non-zero first columns and `b[1] ≠ 0`; they are safe for
  a different reason: none of their stages has `a_ii = 0`, so `evaluate_source` is never called (the single-source RHS is
  `(U_out - U_in)/(dt a_ii)`). The conclusion is right, the reason is not. Also, "turn the run into NaN (loudly)" relies on the new
  snapshot check, which misses the last interval (Finding 1). Suggested wording: "evaluated only at stages with `a_ii = 0`; in the
  shipped tableaus (IMEXEuler, ARS233) those stages have a zero column in A and b". Note: with several implicit sources
  `_implicit_rhs(sources::Tuple, …)` does call `evaluate_sources` at `U_out = f_eq`, giving `0/0 = NaN` for τ = 0; no shipped
  configuration combines BGK with a second implicit source.

## Item-by-item (round-2 findings and the open round-1 items)

- **N1 (blow-ups with a finite step): NOT OK (partly).** Intermediate snapshots are now checked (non-finite → stop, ×1e8 → warn once), the
  regression test fails on the old code (`probe_stop_old.out`: no warning) and passes now. But the final slot is never checked, so
  with `snapshots = 1` nothing changed and blow-ups in the last interval stay silent (Finding 1). Cost: one O(N·M) host pass per
  snapshot over a copy `saveData!` already made — negligible, not on the per-step path. Growth warning: no false positives found;
  zero initial states are skipped (`u0_scale > 0`), ghosts are removed by default in the runners and finite anyway, Float32
  `1e8·u0_scale` overflow only disables the warning, and HyperCloud has no growing source terms (a 1e8 growth would need e.g. a
  tiny perturbation on a zero background driven by an instability — only a warning, acceptable).
- **N2 (zero wave speeds stop at t = 0): OK, with a side effect.** Zero velocity reaches tmax without warnings (test fails on the old
  code: `t = [0, 0]` plus warning). But `Inf` is now also accepted for an all-NaN state and a fixed `dt = Inf` (Finding 2).
  Stopping leaves consistent data for the runners: on a stop at snapshot k the slots k+1..snapshots stay unassigned (dropped by
  `isassigned`), the final slot repeats the state at the stop time, no NaN time is recorded (`all(isfinite, t)` holds in every probe).
- **N3 (`:Grid_bc_map`): NOT OK (partly).** Docs and test comment fixed and accurate for 0.7.9 (`parse_bc`, called by `build_domain`);
  `CLAUDE.md:49` unchanged (Finding 3).
- **N4 (BGK τ = 0 at `a_ii = 0` stages): OK** as a documented hazard (comment instead of code), but the comment's justification is
  inaccurate for three of the five tableaus (Finding 4).
- **N5 (absolute tolerances in the exact Euler solver): OK to leave open; I agree it is low.** `src/PDEs/euler.jl:151-157,166` is
  unchanged; the closure is only a reference solution, all shipped examples/tests use O(1) data where round 2 reproduced Toro's Tests
  1–5 to < 2e-4 in Float64 and Float32; only data with pressure scales ≲ 1e-6 would be affected. Still a cheap fix for later.
- **Round-1 6 (early-stop warning): NOT OK (partly)** — follows N1/N2: much improved, last interval / `snapshots = 1` and the all-NaN
  `Inf` path remain (Findings 1, 2).
- **Round-1 11b (Burgers closures on periodic domains): OK.** The note in `docs/src/PDEs/burgers.md:25-27` is accurate: the closures
  in `src/PDEs/burgers.jl` never fold positions (no periodic handling), so for a Riemann problem on a periodic domain they are wrong
  near the wrap-around jump from t > 0, which the "exact only while the solution near the boundary is still the initial state"
  wording covers.

## Minor issues

  collapsed / not finite … the state has probably blown up" (`probe_stop_new.out`); an up-front `ArgumentError` would be clearer
  (see Finding 2).
- The stop message says "stopped at t = T before tmax = T" when a step jumps to tmax (Finding 2 path); harmless once Finding 2 is fixed.
- Duplicate snapshot times when one step crosses several snapshot times (e.g. velocity 0: `t = [0, 0.1, 0.1]`, slot 2 holds the
  state at 0.1 although it is "the" 0.05 slot; labelled correctly) — pre-existing, noted in round 2.
- `docs/src/configuration.md:59` says the alias is HyperCloudCore's `build_domain`; precisely it is `parse_bc` (called by `build_domain`).

## Verdict

The change set is a clear improvement and the default suite passes (1065 tests). N2 and round-1 11b are resolved, the docs for
`:Grid_bc_map` and the periodic Burgers closures are accurate, and the new tests are real regression tests (both fail on the old
loop). The blow-up detection is incomplete, though: the last stored snapshot is never checked, so runs with `snapshots = 1`, and
blow-ups after the second-to-last snapshot, still end without a warning (Finding 1, medium), and accepting every infinite step lets an
all-NaN state or `dt = Inf` jump silently to tmax, which the d4fe5e4 loop reported (Finding 2, low). Findings 3 and 4 are small doc
fixes. Fixing Findings 1 and 2 needs only a few lines in `solve_equation` plus two short tests.
