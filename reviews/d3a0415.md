## Findings

### 1. A stop on a non-finite state reports the same blow-up twice — low — CONFIRMED
- **Where:** `src/time_integration.jl:188-192` / `:164-169` (stop) and `:230-234` (final-slot check).
- **What:** after a stop at intermediate snapshot k (or in the new infinite-CFL branch), `snap_counter <= snapshots + 1` holds,
  so the final slot is written with the same state and `_check_snapshot(...; final = true)` warns again ("the state at t = … is
  not finite (blown up).") about the state that was just reported. Harmless for correctness (data are consistent: finite times,
  final slot = state at the stop time, unreached slots unassigned), but the second warning without "stopped before tmax" can be
  read as "the run reached the end and blew up at the last moment".
- **Evidence:** `probe_d3a_new.out`: "lin CFL5 snaps=10" → `#warn = 3` (growth + "not finite" twice at t = 80.05);
  "Burgers NaN snaps=4" → `#warn = 2` (stop + final at t = 0.0). The new tests use `match_mode = :any`, so they don't notice.
- **Fix:** keep a `stopped` flag (set on every `break` except "tmax reached up to round-off") and call the final
  `_check_snapshot` only when `!stopped`; or skip it when `ts[snapshots + 1] == ts[snap_counter - 1]` was already checked.

### 2. `:Time_CFL => Inf` still takes one silent step of size tmax — low — CONFIRMED
- **Where:** `src/time_integration.jl:164` (`is_cfl && dt_step == T(Inf)` does not distinguish "no wave moves" from an infinite
  CFL number).
- **What:** round 3 suggested accepting the infinite step only for `is_cfl && isfinite(dt_inp)`. The commit fixed the all-NaN
  state and fixed `dt = Inf` (both now stop), but an infinite CFL number with a finite state still advances to tmax in one step and
  returns a finite, wrong result without any message. This is a configuration error, unlikely in practice, hence low.
- **Evidence:** `probe_d3a_new.out` "lin CFL = Inf": `t = [0, 0.1, 0.1]`, max\|u\| = 0.668 instead of 1.0, `#warn = 0`.
- **Fix:** `if is_cfl && isfinite(dt_inp) && dt_step == T(Inf)`, or reject a non-finite/non-positive `dt` (CFL or fixed) up front
  with an `ArgumentError` before the loop.

No other defects found in the changed lines:
- `_check_snapshot`: the growth test is now `scale > 1e8 * u0_scale` with a Float64 literal (was `T(1e8)`); for Float32 the product
  is promoted to Float64, so it cannot overflow — fine (slightly better than before). Return type is `Tuple{Bool, Bool}`; the caller's
  `blown_up, growth_warned = …` and `break` logic are unchanged in effect.
- Infinite-CFL branch: `host_view(pg.rhos, pg.meta.N)` is a view for host arrays and an `Array` copy for device arrays
  (`src/device.jl:48`), so no scalar indexing on the GPU path; it uses the current `pg.meta.N`, so it follows adaptivity. It only runs
  when the CFL step is exactly `Inf` (not the hot path). It includes ghost particles (unlike the snapshot check with the runners'
  default `remove_ghosts = true`); ghosts are filled by the BCs from interior states, so they are non-finite only if the interior is,
  and the suite (zero-velocity test) shows no false positive. Partial-NaN states whose finite part has zero wave speed are caught
  too (any NaN component → stop).
- Fixed-`dt` handling: `!(isfinite(dt_step) && dt_step > 1e-12)` rejects ±Inf, NaN, ≤ 1e-12; a CFL step of −Inf (negative CFL with
  zero speeds) also lands here. The message picks "collapsed" vs "not finite" correctly.
- Final slot: checked in all exit paths (normal end, stop, round-off end); with `snapshots = 1` the only post-t=0 state is now
  checked; the growth warning is also applied (once). Returned data are consistent in every probe case (`all(isfinite, t)`, final
  slot = last state, unreached slots dropped by `isassigned`).

  `bgk_sources` rejects for τ = 0. The comment is now correct for all five shipped IMEX tableaus. (Still unmentioned, as in round 3:
  with several implicit sources `_implicit_rhs(::Tuple, …)` evaluates at `U_out`; no runner combines BGK with another implicit
  source, so no action needed.)
