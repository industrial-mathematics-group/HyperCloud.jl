Time Integration

solve_equation runs the time loop: it computes the step size, advances the particle grid with the chosen Runge–Kutta or IMEX stepper (HyperCloudCore's Time Stepper), applies particle adaptivity between steps if it is enabled, reports progress, and stores snapshots.

Time step

  • Fixed: with is_cfl = false, dt is the physical time step.
  • CFL: with is_cfl = true (:Time_CFL in a configuration), dt is a CFL number and the physical step is recomputed every iteration as dt * get_time_step(pg, eq, div_interp). This uses the current wave speeds of the equation and the MLS derivative stencils of the grid; see HyperCloudCore's CFL time step for the formula and measured limits.

The last step is shortened so the run ends exactly at tmax.

If the step collapses (below $10^{-12}\,t_{max}$, relative, so no time scale is assumed) or is not finite (NaN states or unbounded wave speeds after a blow-up, or an infinite CFL number or fixed step), or a stored intermediate snapshot is not finite, the loop stops before tmax with a warning that gives the time reached; a non-finite final snapshot (at tmax) gives a warning too. Each blow-up is reported once. The snapshot check also catches blow-ups the step doesn't see: fixed time steps, equations with constant wave speeds (linear advection, BGK, kinetic runs) and CFL estimates that skip NaN particles. The final slot then holds the state at that time, snapshots that were not reached are dropped by the runners, and no NaN time is recorded. The runners still return the data, so check the warning or t[end]. A snapshot more than $10^8$ times larger than the initial state gives a warning (once) without stopping the run. If no wave moves at all (an infinite CFL step with a finite state), the run advances straight to tmax.

Snapshots

snapshots + 1 states are stored, at the target times range(0, tmax, length = snapshots + 1); snapshots must be at least 1 (an ArgumentError otherwise).

  • Snapshot 1 is the initial state at t = 0.
  • Each further snapshot is taken at the end of the first step that reaches its target time, so t[k] can lie slightly after the target.
  • The final state is always stored in the last slot.

saveData! copies positions and states (and the snapshot fields, see below) into new arrays, so later steps do not modify stored snapshots. With remove_ghosts = true only non-boundary particles are kept. The runners pass :remove_ghosts from the configuration (default true); solve_equation itself defaults to false.

Progress output

  • show_progress = true: a progress bar.
  • show_progress = false: an @info line with the percentage and an ETA (HH:MM:SS) every progress_interval seconds, which is better suited for log files.

The runners take both settings from global switches: enable_progress_bar!(false) and set_progress_interval!(seconds).

The loop also logs the execution backend of the parallel loops (see set_backend!).

Return value

solve_equation returns the run as a PDEStudioCore LSimData (create_sim_data), ready to be saved or plotted:

  • sim.x[k], sim.u[k], sim.t[k]: the stored snapshots. These are the snapshots the run reached, so a run that stopped early has fewer than snapshots + 1.
  • sim.u[k] holds snapshot_state(u) of every particle's state: the state itself by default, the macroscopic moments for the kinetic and BGK runners.
  • sim.params: the keyword params, the run's parameters. They name the dataset's file in PDEStudioCore's pipeline.
  • sim.metadata: the run's metadata (run_metadata):
    • the HyperCloudCore version, the backend and the float type;
    • the steps and the time reached;
    • :stopped_early, :finite;
    • :restarts with a checkpoint.
  • sim.stats: the statistics of the run, each registered with the dimensions it keeps:
statistickeptvalue
:RuntimeSymbol[] (a number)wall-clock time of the loop in seconds (all attempts of a resumed run)
:k_stepSymbol[]time steps taken (all attempts)
:final_particle_countSymbol[]particles of the grid at the end, ghosts included
:particle_count:timeparticles stored in each snapshot
each of snapshot_fields:allthat per-particle array of the grid at each snapshot, aligned with sim.x[k]

snapshot_fields (keyword, default DEFAULT_SNAPSHOT_FIELDS = (:volumes, :particle_orders)) names the per-particle arrays of the grid stored with every snapshot: :volumes, :particle_orders, :neighbor_counts, :is_boundary, :tags, :wall_distances. A method of snapshot_field for another name adds a field.

  • The fields are copied with the positions (on a device: host copies). With remove_ghosts they are copied for the same particles.
  • A checkpoint stores them with the snapshots, so a resumed run returns them complete.
  • More statistics can be added to the returned dataset with PDEStudioCore's add_stat!.

PDEStudioCore stores a statistic with the dataset's component count and float type: a per-particle field holds M copies of each value. The runners therefore store no fields for the full kinetic states (:save_relax) unless :snapshot_fields is given.

API

HyperCloud.solve_equation — Function
solve_equation(timestepper, eq, pg, tmax, dt; kwargs...) -> LSimData

The primary simulation orchestrator governing the main time-stepping loop.

Arguments

  • timestepper::TimeStepper: The selected Runge-Kutta or IMEX time integrator.
  • eq::HyperbolicPDE: The physical equation system.
  • pg::ParticleGrid: The active mesh-free domain configuration.
  • tmax::Real: The final simulation time.
  • dt::Real: The baseline time step.

Keyword Arguments

  • is_cfl::Bool: If true, dt is treated as a CFL number, and the physical time step is dynamically computed at each iteration using the grid and interpolator properties.
  • snapshots::Integer: The number of output intervals (at least 1); snapshots + 1 states are stored, including t = 0.
  • remove_ghosts::Bool: Strips boundary/ghost particles from the returned snapshot data if true.
  • show_progress::Bool: Toggles visual progress tracking.
  • progress_interval::Real: Sets the refresh rate (in seconds) for logging the simulation's progress and calculating the ETA.
  • adaptivity: a ParticleAdaptivity applied between steps (particle insertion/merging on moving grids), or nothing.
  • checkpoint: a Checkpointing (or nothing): the state of the run is saved to its file every every seconds of wall time, and a run that finds the file resumes from it (the grid, the states and the snapshots stored so far are restored before the first step; the initial conditions set before are overwritten) and continues bit for bit as the run that wrote it would have. The file stays after the run (remove_checkpoint).
  • snapshot_fields: the per-particle arrays of the grid stored with every snapshot (snapshot_field names, default DEFAULT_SNAPSHOT_FIELDS = (:volumes, :particle_orders); () stores none).
  • snapshot_state: what is stored of a particle's state u: snapshot_state(u) (default identity, the state; e.g. u -> moments(eq, u) stores the macroscopic moments of a kinetic state). The blow-up check runs on the stored values.
  • params: the parameters of the run, the dataset's params (they name its cache file in PDEStudioCore's pipeline).
  • xmins, xmaxs: the extent of the dataset (default: the box of the grid's geometry).

Returns

  • The run as a PDEStudioCore LSimData: sim.x[k], sim.u[k], sim.t[k] of the stored snapshots (the ones reached: a run that stopped early has fewer than snapshots + 1), the metadata of the run (run_metadata: versions, backend, steps, the time reached, :stopped_early, :finite, :restarts) and its statistics, each registered with the dimensions it keeps: :Runtime (wall time of the loop in seconds) and :k_step (steps), both over all attempts of a resumed run, :final_particle_count (numbers), :particle_count (the particles stored per snapshot) and every name of snapshot_fields (one value per particle and snapshot, aligned with sim.x[k]).

The loop stops early with a warning that gives the time reached if the time step collapses (below 1e-12 tmax) or is not finite, or if a stored snapshot is not finite (a blown-up state; this also covers fixed time steps and equations with constant wave speeds, whose step never collapses). Every stored snapshot is checked, the final one included. The last stored state is the one at that time, and the snapshots that were not reached are not part of the dataset. Each blow-up is reported once (the final slot of a stopped run is not checked again). A snapshot that grew by more than a factor 1e8 over the initial state gives a warning (once) but does not stop the run. An infinite CFL step with a finite state and a finite CFL number (no wave moves) advances straight to tmax; an infinite CFL number (or fixed step) stops at once.

source
solve_equation(timestepper::BlockTimeStepper, eq, pg, bs::BlockState, tmax, dt; reduce, kwargs...)

The time loop of solve_equation for the block pipeline: the block state bs is advanced, and the stored snapshots hold reduce(Y, N, nb, i) per particle (the macroscopic moments, e.g. (Y, N, nb, i) -> block_moments(bk, Y, N, nb, i); a kernel function, run on the storage of the state and copied to the host), never the full distribution; adaptivity is applied between steps on every block. The other keywords and the returned LSimData as for the standard pipeline (a checkpoint saves and restores the block state with the grid).

source
solve_equation(devs::BlockDevices, eq, tmax, dt; reduce_partial, partial_type, kwargs...)

The time loop of a block state split over devices: devs(t, dt) advances, and the stored snapshots hold the sum over the parts of reduce_partial(Y, N, nb, blocks, i) (a kernel function of a part's blocks, the moments of a block range: (Y, N, nb, blocks, i) -> block_moments(bk, Y, N, nb, i, blocks)), of type partial_type, computed on every device and summed on the host (host_reduction). No adaptivity. The other keywords and the returned LSimData as for the block state (a checkpoint holds the blocks of all parts: it resumes on any split, or on a single block state; the snapshot fields are those of the first part's grid, the same cloud on every part).

HyperCloud.saveData! — Function
saveData!(xs_storage, us_storage, ts_storage, snap_idx, pg, current_t, remove_ghosts; fields = (), snapshot_state = identity)

Extracts and archives the simulation state at a specific snapshot index.

Details

  • Records the current time into ts_storage.
  • If remove_ghosts is true, it filters out boundary particles and saves only the active domain core. Otherwise, it copies the entire grid.
  • Allocates new state and position vectors for the targeted snapshot and copies the corresponding views from the particle grid.
  • fields: name => storage pairs; slot snap_idx of each storage gets the grid's snapshot_field name of the same particles.
  • snapshot_state: the stored value of a particle's state u is snapshot_state(u) (e.g. the macroscopic moments of a kinetic state); identity stores the state.

HyperCloud.snapshot_field — Function
snapshot_field(::Val{name}, pg::ParticleGrid) -> AbstractVector

The per-particle array of the grid that solve_equation stores with every snapshot for name in its snapshot_fields (as a statistic that keeps all dimensions, converted to the run's float type; the ghosts are left out with the positions when remove_ghosts is set). The array may live on a device and be longer than the particle count (the first pg.meta.N entries are read). Defined names:

  • :volumes: the particle volumes (Σ V u is the discrete mass of a moving or adapted cloud);
  • :particle_orders: the consistency order of every particle after the last step (lowered by MOOD);
  • :neighbor_counts: the number of neighbours;
  • :is_boundary: 1 for a ghost (boundary) particle, 0 for an interior one;
  • :tags: the boundary tag (0 for an interior particle);
  • :wall_distances: the distance of a ghost to its wall.

A method for another name makes it available (HyperCloud.snapshot_field(::Val{:my_field}, pg) = …).

source
HyperCloud.DEFAULT_SNAPSHOT_FIELDS — Constant

The per-particle arrays solve_equation stores with every snapshot by default: (:volumes, :particle_orders).
